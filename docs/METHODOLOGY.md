```

                ↓                        ↓

                                         ↓
                                  model/calibration.py → calibration.json
```

`backtest → reweight → calibrate → build` in order. See

## Devigging the market

Sportsbooks bake a margin (the "vig") into both sides of a two-way market.
To recover a fair probability we just normalise:

```
p_i_implied = American → implied prob (with vig)
p_i_fair    = p_i_implied / Σⱼ p_j_implied
```

Example: a `-110 / -110` line implies `0.524 / 0.524`. After devig:

```
p_home_fair = 0.524 / (0.524 + 0.524) = 0.500
p_away_fair = 0.524 / 1.048           = 0.500
```

Code: `flashcat.types.devig_two_way`.

## Per-source accuracy

For each (sport × source), over the rolling 365-day window in
`source_history.db`, we compute:

### Brier score
```
BS = (1/n) Σ (p_i − y_i)²        where y_i ∈ {0, 1}
```
Lower is better. 0.25 is the score of a coin flip. Anything **above 0.25 is
excluded from the blend** outright — those sources are losing signal, not
adding it.

### Log loss
```
LL = −(1/n) Σ [ y_i log(p_i) + (1−y_i) log(1−p_i) ]
```
With `p_i` clipped to `[0.001, 0.999]` so the log doesn't blow up.

### Accuracy
```
acc = (1/n) Σ 𝟙[ (p_i ≥ 0.5) == y_i ]
```

### Calibration slope
Fit `y_i ~ σ(α + β · logit(p_i))` by Newton steps on the binary
cross-entropy loss. `β = 1` means perfectly calibrated. `β < 1` means the
source is systematically too confident; `β > 1` means under-confident.

### ROI
Flat $100 bets on the higher-probability side, paid at the market closing
decimal odds:

```
profit_i = 100 × (decimal_close − 1)   if pick won
         = −100                         otherwise
ROI      = Σ profit_i / Σ stake_i
```

All five are persisted into `source_history.meta` per (sport, source,
window_end) so the site can plot rolling 30-day trends and the reweighter
can read them back out.

## Hybrid score and softmax weights

For each sport's pool, we rank sources by a hybrid score that fuses Brier
improvement with rolling ROI:

```
score_i  = (NAIVE_BRIER − BS_i)  +  λ · clip(ROI_i, −0.2, +0.2)
weight_i = exp(β · score_i) / Σⱼ exp(β · score_j)
```

Where:
- `NAIVE_BRIER = 0.25` (the score a coin flip gets)
- `β` (default **8**) controls how sharply weight concentrates on top sources
- `λ` (default **0.5**) is how much we let ROI move the ranking when sources
  have similar Brier
- The ROI clip prevents one lucky run from dominating

Configurable via `FLASHCAT_HYBRID_BETA`, `FLASHCAT_HYBRID_LAMBDA`.

### Per-sport eligibility gates
- `nfl` requires **30** graded events (short season).
- All other sports require **50**.
- Brier > 0.25 → excluded.

Sources that fail eligibility get listed under `payload.excluded[sport]`
in `data/source_weights.json` so Phil can see *why* the blender ignored
them.

Code: `flashcat.model.reweight`.

## Platt calibration of the blend

After we blend N sources we may still be systematically over- or
under-confident. We fit per-sport Platt scaling on the rolling 365-day
window:

```
α, β  =  argmax  Σ  log σ(α + β · logit(p_blend))^y · σ(...)^(1−y)
p_calibrated = σ(α + β · logit(p_blend))
```

Newton steps on the binary cross-entropy until convergence; we reject the
fit if `β ∉ [0.2, 3.0]` (degenerate). Coefficients persist to
`data/calibration.json` so the live build applies them without re-fitting.

Code: `flashcat.model.calibration`.

## Kelly fractional staking

For each candidate bet:

```
b = decimal_odds − 1
p = blended calibrated probability of our pick
q = 1 − p
f* = (b·p − q) / b                    Full Kelly
f  = max(0, fraction × f*)            Fractional Kelly
```

We use **quarter Kelly** (`KELLY_FRACTION = 0.25`) by default. The bet is
**skipped** if any of:

- `f < 0.005` (variance floor: < 0.5% of bankroll)
- `edge = p − p_market_fair < 0.03` (3 pp edge gate)
- `|p − p_market_fair| < 0.02` (no-bet band around the market)
- Rolling 365-day blended ROI for this sport is negative → RESEARCH MODE,
  no live recommendations.

Otherwise:

```
stake = bankroll × f         capped at 2% of bankroll
                              rounded to nearest $5
```

Default bankroll: $10,000 (env `BANKROLL`).

Code: `flashcat.model.staking`.

## Closing-line value (CLV)

CLV measures how much better than the closing line we got into a bet.

```
clv_pp = 100 × (p_blend_at_bet − p_pinnacle_close)
```

Positive CLV means we beat the sharpest book. Over a large enough sample
CLV is the *only* metric that reliably predicts ROI — even a +1 pp CLV
average is enough to flip a losing bettor into a +EV one once volume
catches up.

Pinnacle is the canonical "close" because their book is sharp by design
(no recreational squareness, lower limits ≠ less sharp).

Code: `flashcat.source_history.avg_clv_pp`.

## Walk-forward strictness

A backtest is only honest if predictions at time `t` use no information
from `t' ≥ t`. We enforce this per source:

| Source | Walk-forward guarantee |
|---|---|
| 538 MLB / NBA / NFL Elo | CSV row was published pre-game; outcomes filled in after — implicit guarantee |
| Sackmann Elo | Ratings are rebuilt walk-forward in `_SackmannElo.predictions` |
| MLB Pythagorean | Season RS/RA totals updated AFTER each game; HFA constant |
| Tennis-data closes | Closing odds are pre-match by definition |
| ESPN BPI / FPI | `gameProjection` is pre-game per ESPN docs |
| Dimers | **Live-only**. We do NOT use Dimers for historical backtest because their site shows post-hoc updated predictions |
| FanGraphs | **Live-only**. Same reasoning |
| Pinnacle live | **Live-only**. Used for CLV reference vs the time-of-bet |

Backtest-eligible sources are tagged in `data/source_scoreboard.json`
under `per_sport[sport].sources[<source>]` so it's auditable.
