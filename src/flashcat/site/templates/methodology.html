Methodology

1. The universal bet

Flashcat bets $100 flat on every event. No Kelly, no fractional sizing, no abstention. The research question is: can a probability blend, scored across many sources, beat the closing market on $100-flat? Position sizing is a Phase 2 problem.

2. Probability blending

For each event, we collect a home-win probability from every source that has one:

  • The Odds API — devigged consensus across US books
  • ESPN scoreboard / predictor — ESPN's gameProjection field
  • Polymarket — last-trade price on the relevant market
  • Market consensus — devigged moneyline from book-average closing odds
  • (Phase 2: Pinnacle, DraftKings, FanDuel, Kalshi, FiveThirtyEight, Massey/Sagarin, KenPom, BPI — stubs are in the codebase)

Each source has a weight w_s ∈ [0, 1] with Σw_s = 1. The blended home probability is:

p_blend(home) = Σ_s ( w_s × p_s(home) )

On a fresh deploy, weights are uniform across active sources. After each backtest, weights update to favor sources with better calibration.

3. Pick rule

We bet $100 on whichever side has the higher blended probability. The only exception is the tie-breaker band: when p_blend(home) ∈ [0.48, 0.52], we bet the underdog by moneyline. This encodes the "favorite is a sucker's bet" hunch — in coin-flip games, the market premium on the slight favorite has historically been overpriced.

4. Source reweighting (PR #21 — infrastructure only)

The reweighter scores each source on a hybrid Brier + ROI signal and softmax-weights them into the per-sport blend. PR #21 ships only the infrastructure needed to run hold-out experiments — not the proposed tuning from PR #19 (β = 16, ROI exclusion floor at −1%), which did not survive out-of-sample validation. Defaults shipped:

  1. Softmax (β = 8). Per-source weights are computed as softmax(β · score_s) where score_s = (0.25 − B_s) + 0.5 · clip(ROI_s, ±20%). β is the prior default; PR #19 proposed β = 16 but the multi-sport hold-out (PR #20) showed it was overfitting, so PR #21 reverts to 8. Re-tunable via FLASHCAT_BLENDER_BETA once a sport demonstrates positive hold-out edge.
  2. ROI exclusion floor — mechanism in, default off. The infrastructure to hard-exclude a source whose rolling-window ROI is below FLASHCAT_BLENDER_ROI_FLOOR (with ≥ FLASHCAT_BLENDER_MIN_BETS_FOR_EXCLUSION graded bets) is in place, but the default floor ships at −1.0 (≡ −100% ROI, unreachable in practice) so no source is excluded. Re-enable via the env var when a sport's hold-out evidence supports it.
  3. Min-source fallback. If exclusion is re-enabled and would leave fewer than two surviving sources for a sport, the exclusion is suppressed (you need ≥ 2 sources to blend at all) and an explicit min_sources_floor_active entry is emitted to the excluded list.
  4. Low-sample cap. A source with fewer than 50 graded bets keeps its natural softmax weight but is capped at 1/N of the surviving pool, so a small-n source can’t dominate just because its score happened to be best on a noisy sample.

Snapshots of every weight update are saved to SQLite (weight_history table) so we can audit drift, and the excluded list is shipped in source_scoreboard.json::weights.excluded for inspection.

4a. Walk-forward hold-out validation

PR #21 ships the walk-forward hold-out runner (python -m flashcat holdout) as the central de-risking deliverable. It splits data/source_history.db into a training window (2022-01-01 → 2023-12-31) and a held-out window (2024-01-01 → 2024-12-31), fits the reweighter on training-only data, and applies those frozen weights to the held-out predictions. The current evidence (PR #20 backfill across MLB, NFL, ATP, WTA) is that no sport shows a credible positive hold-out edge — see the homepage banner. The live source-weight file is still fit on the full rolling window; the hold-out exists purely as a diagnostic.

4c. Two-way market settlement bug fix (PR #21)

The PR #19 hold-out runner had a settlement bug: _blended_roi grabbed the first row's market_close_decimal and settled BOTH sides of a two-way market at that single decimal. With per-source rows storing decimals on whichever side the source had picked, a blended pick on the OPPOSITE side could settle at the wrong price (the first hold-out run produced fake +35% ROIs). PR #21 fixes the function: each event is settled at the picked side's own decimal odds, with the missing side derived from market_close_home via the no-vig two-way inverse away_dec = p_h × home_dec / (1 − p_h). The same fix is applied to flat_stake._simulate_blended.

4b. Per-sport Platt calibration

After exclusion + reweighting, each sport’s blended probability is passed through a per-sport Platt transform σ(α + β · logit(p)). Coefficients are re-fit on the post-exclusion blend (not the pre-PR blend) and persisted to data/calibration.json. The fit is rejected and the sport falls back to pass-through whenever fewer than 50 calibration pairs are available or the fitted slope falls outside [0.2, 3.0].

5. The two signal flags

5a. Chalk-overpriced (favorite-longshot bias)

For each event we compute the devigged implied probability of the favorite from book averages. If that implied probability is more than 5 percentage points above the model's blended probability for the favorite, we flag chalk-overpriced. This is the modern restatement of the classic favorite-longshot bias result.

5b. Reverse line movement + cross-book dispersion

For events where we have both opening and current moneylines:

  • RLM: if the home implied probability moved ≥ 2 percentage points away from opening, we flag the direction of the move (reverse-line-movement-toward-home or toward-away). Sharp money pushes lines against the public bet distribution.
  • Book dispersion: if the spread between the highest and lowest implied probabilities on the underdog side across books exceeds 4 percentage points, we flag book-dispersion-dog. A wide spread means books disagree, and the soft books are exploitable.

6. Backtest

Phase 1 backtests on the most recent complete NFL season via nfl_data_py. Each historical event is simulated as a $100 flat bet at the book-average closing line; outcomes determine P&L. The bankroll curve, calibration bins, and ROI slices (overall / chalk-only / dog-only / RLM-only / dispersion-only) are recomputed every run.

6a. Flat-stake headline simulator

The homepage Backtest Profitability table is computed by a separate simulator (flashcat.backtest.flat_stake) that mirrors Phil’s research question literally: “drop $100 on every prediction that beats the devigged market close by ≥ 3pp.” Per-(sport, source) and blended rows are computed end-to-end against data/source_history.db; the per-event Recommended Plays cards on the homepage use Kelly sizing instead. When the predictions ledger lacks settlement prices for a sport, the simulator falls back to reconstructing stake/profit from the persisted meta rows (n_bets × $100, roi × stake) and tags the result with roi_source = "weighted_per_source_meta" so it’s clearly distinguishable from a per-event sim.

6b. LIVE-mode floor

A sport ships LIVE only if its blended backtest ROI is ≥ FLASHCAT_LIVE_ROI_FLOOR (+2%, kept from PR #19 as a safety margin given hold-out shows no real edge anywhere) with at least FLASHCAT_LIVE_MIN_BETS scored bets (200). Sports between +2% and +4% are LIVE but flagged marginal (yellow tint). Everything else stays in RESEARCH mode — odds, probabilities, and rationale are still displayed for transparency, but no $ stake recommendations are issued.

7. What is out of scope (Phase 1)

  • Live in-game probabilities
  • Real-money execution
  • Account / bankroll / Kelly sizing
  • Sport-specific deep models (those are Phase 2 — Flashcat is the blender, not the sport model)
  • Scraping behind login walls
